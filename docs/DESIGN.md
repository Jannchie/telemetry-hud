# 设计语言

Telemetry HUD 的视觉与交互规则。实现以 [`hud/index.html`](../hud/index.html) 为准，本文记录其中的约定和取舍理由；做同风格的新界面（如 music-hud）时按这里的规则走，改了约定要同步更新本文。

## 1. 原则

- **一切从线生长。** 画面由一套左右镜像的引导线构成，每个组件都是某条线被打断后的一段，或被线围出的区域里的读数。不放独立的卡片、面板、图标。
- **只显示真实数据。** 读不到的值显示 NO SIGNAL，不推测、不补默认值、不用模拟数据填充。模拟数据只在 `?demo=` 下出现。
- **安静的常态，明确的异常。** 平时以中性灰线和少量主色为主；颜色饱和度、闪烁、声音只留给负载、告警、掉线这类需要注意的状态。
- **机械感而非装饰感。** 动效都对应一个物理隐喻：信号脉冲、计数器滚动、霓虹管点亮、示波器扫描。不做无意义的循环动画。
- **对称。** 左右成对的信息（CPU / GPU、读 / 写、上行 / 下行）放在镜像位置，用同一套几何与动效。

## 2. 画布与坐标

- 所有绘制使用 **1920×1080 设计坐标**，按短边等比缩放后居中；底部额外预留 `BOTTOM`（默认 80）设计像素给任务栏。
- 超宽屏不拉伸构图：翼线固定画到 x=60，多出的部分用直线延伸到屏幕边缘（`endDot()`），保证沿线的分段比例不随屏幕变化。
- 镜像轴是 x=960。右侧几何一律由左侧经 `M(p) = (1920 − x, y)` 镜像得到，不单独手写坐标。
- 背景只有两样：径向渐变（`bg0` → `bg1`）和 48px 间距、1.5px 的点阵（`fg` 4.5% 不透明度）。

## 3. 构图骨架

```
              冠线（中轴向上分出，45° 落到 A 的节点）
   A 上翼 ─────────╲                     ╱───────── A 上翼
                    ╲   ┌─ 透镜上缘 ─┐  ╱
   地平线 ───────────── ◇  中央透镜  ◇ ───────────── 地平线
                    ╱   └────────────┘  ╲
   B 下翼 ─────────╱                     ╲───────── B 下翼
              龙骨（B 的节点 45° 下沉，水平穿过中轴底部）
```

| 线 | 承载内容 |
| --- | --- |
| 中央透镜 | 主读数；上缘为内存。两端尖角是所有翼线的发源点 |
| A 上翼 | 负载格子条 → 节点（冠线接入）→ 核心梳齿 / 显存块 → 外延射线 + 日志 |
| B 下翼 | 存储总量 / 温度 → 节点（龙骨接入）→ 分盘读写 → 外延射线 + 流动粒子 |
| 地平线 | 系统日志、时间轴；在台阶 `HSTEP` 处下折，时间轴到台阶为止 |
| 冠线 | 有电池时兼作电量条，台式机上只是一条细线 |
| 龙骨 | 网络波形 |
| 括号 | 纯装饰，在翼线斜段外侧，上下两段与 A / B 斜段平行 |

几何规则：

- 路径用折线 + 拐角过渡弧（`poly(pts, r)`）生成，直线为主，拐角半径 6–36。
- 斜向分支统一用 **45°**；透镜上缘与支腿共用 dx:dy = 30:46 的斜率，支腿就是斜边越过尖端的延长，形成"道岔"。
- 所有路径按弧长参数化（`u ∈ [0, 1]`），组件位置用弧长比例表示（见 `U` / `UB`），并带一条朝"外侧"的统一法线，内容贴在线的哪一侧由偏移的正负决定。
- 格子条必须完全落在直线段内，避开拐角过渡弧，否则格子会跟着弧线歪掉。
- 存储和主板相关的挂件与主线保持同一平面，不单独分层（否则线在接点处会断开）。

## 4. 线条

| 线宽 | 颜色 | 用途 |
| --- | --- | --- |
| 2.5 | `hot` | 外延射线、电量条，以及超宽屏延伸段 |
| 1.5 | `line` | 骨架主线、信号脉冲（`fg`） |
| 1.25 | `fg` / `line` | 节点小环、冠线 |
| 1 | `line` / `faint` | 刻度、日志标签框、格子条底线、次级分隔 |

- `lineCap = 'butt'`，`lineJoin = 'round'`。线头是平的，转角是圆的。
- 线在节点处**断开**，留一个半径 4 的小环（`node()`），不画实心交点。
- 路径终点用实心圆点（半径 4.5，`fg`）。

## 5. 颜色

每套主题 12 个 token，组件只引用 token，不写死颜色：

| token | 语义 |
| --- | --- |
| `bg` `bg0` `bg1` | 页面底色；背景径向渐变的中心 / 边缘 |
| `fg` | 主文字、节点、粒子 |
| `dim` | 次要文字、标签 |
| `line` | 骨架线、边框 |
| `faint` | 最弱的分隔线、梳齿底线 |
| `hot` | 负载、射线主色；也是 NO SIGNAL 的警示色和控件选中色 |
| `cool` | 流量、次要数据、日志正文的补充段 |
| `mark` | 标记点、显存、GPU 饱和告警 |
| `alt` | 内存压力告警 |
| `heat` | 高温告警 |

不透明度层级：未填充的格子 0.16，格子条两端刻度 0.6，高亮扫描格 0.8；背景点阵 0.045。

告警配色：CPU 饱和 `hot`，GPU 饱和 `mark`，内存压力 `alt`，下行激增 `cool`，过热 `heat`。电量 > 50% 用 `cool`，20–50% 用 `mark`，≤ 20% 用 `hot`。

现有 9 套主题：`ember`（默认）、`glacier`、`phosphor`、`classic`、`amber`、`synthwave`、`sakura`、`cobalt`、`mono`。

换色只需要换 token：Canvas 每帧从 `C` 取色，DOM 面板从 `--hud-*` CSS 变量取色。`setTheme()` 换掉 `C`（换了底色主题才重画背景层），面板同步时再把 token 写进 CSS 变量，组件代码不需要改动。

**自定义颜色**只开放五个强调色（`hot` `cool` `mark` `alt` `heat`），覆盖在当前主题之上，换主题时保留；底色和中性灰（`bg*` `fg` `dim` `line` `faint`）始终跟随主题，避免用户调出不可读的组合。三个入口共用 `cfg.colors`：控制面板（色相 / 饱和度 / 亮度滑块 + 色值输入框）、网址参数（`?hot=33ff99`）、Wallpaper Engine 属性（`customcolors` 开关 + `color<名称>` 颜色属性）。面板不用 `<input type=color>`，理由同 `<select>`。

新增主题时：

- 背景保持接近黑（亮度不超过约 10%），`bg0` 比 `bg` 稍亮、`bg1` 稍暗。
- `fg` 带一点主题色相的暖 / 冷倾向，不用纯白（`mono` 例外）。
- `hot` 与 `cool` 的色相要拉开，保证负载和流量一眼可分；`mono` 只靠亮度区分，`mark` 是唯一点缀色，告警仍用彩色。

## 6. 字体

三族，全部本地打包（OFL），不依赖网络：

| 变量 | 字体 | 用途 |
| --- | --- | --- |
| `F.disp` | Michroma | 少量标题、主机名等展示文字（10 / 17px） |
| `F.ui` | Chakra Petch | 标签、日志正文、面板文字 |
| `F.mono` | JetBrains Mono | Canvas 里的数字读数、日志标签、规格表 |

- 主力字号是 **9–12px**，最大读数 22px。HUD 靠大量小字和细线堆出密度，不用大标题。
- 沿线标签的标准样式：`600 9px` Chakra Petch，字距 2px，全大写，`dim` 色，例如 `P-CORE ×12`、`VRAM 6.1 / 16 GB`。
- Canvas 不支持 `tabular-nums`，所以 Canvas 里会变化的数字用等宽字体；DOM 控制面板里的数字用 Chakra Petch 加 `font-variant-numeric: tabular-nums`。
- 中文回退：Microsoft YaHei UI、PingFang SC。

## 7. 组件词汇

| 组件 | 规则 |
| --- | --- |
| **格子条** `cellBar` | 沿路径排列的斜切平行四边形，按格量化填充（不做连续进度）。格宽占步长的 68%，斜切角固定，因此高度可以由细到粗（`[4, 18]`），短边仍互相平行。两端各一条同角度的定位刻度 |
| **梳齿** | CPU 每个逻辑核一根，长度 = 负载；大核 / 小核分两组、中间断开；单核超过 85% 变 `hot` |
| **计数器数字** `odo` | 机械里程表式滚动：最低位随小数连续滚，进位时高位一起滚；前导零以 0.16 透明度显示；可选最低位上下的淡残影 |
| **日志行** `tagLine` | `[tag]` 用 1px 框 + `dim` 等宽字，正文第一段 `fg`、` · ` 之后的部分 `cool`；按每秒 80 字打字输出，末尾带一个 `cool` 光标块。最多三行，透明度 1 / 0.5 / 0.26，逐层横向错开形成平行四边形 |
| **信号脉冲** | 一段 46px 的 `fg` 亮线沿骨架从中心向外跑，跑完停顿一会儿再出发 |
| **流动粒子** | 3×3 方点沿射线移动，两端淡入淡出；流速随负载 / 吞吐变化 |
| **电池** | 左右冠线从外端向中心同步填充，长度 = 电量。充电时粒子流向中心，放电时填充头部呼吸，低于 20% 且未充电时闪烁。没有电池就什么都不画 |
| **NO SIGNAL** | 格子条全空、用 `hot` 描、一格亮块来回扫描（像在搜索信号）；标签 `XXX · NO SIGNAL` 偶尔闪暗。整段信号丢失的大字用红青错位叠印，偶尔横跳 |

## 8. 状态

- **缺失**：每个字段都允许为 `null`，只影响对应组件，其余照常显示。
- **告警**：带迟滞（`hi` 触发、`lo` 解除，如 CPU 90% / 80%），避免在阈值附近反复跳动。告警时屏幕左右边缘出现 160px 宽的呼吸光晕，颜色取最早触发的那一项；同时写一条日志、播放一次告警音。
- **挂载**：某项数据从无到有时，相关组件重新生长一次（见下节），并播放挂载音。

## 9. 动效

- **开屏**按组件分阶段载入（`STAGES`），总长约 3.6 秒，顺序：透镜 → 上翼 → 规格 → 下翼 → 龙骨 → 地平线 → 内存 → 装饰 → 读数格。两种方式：
  - `grow`：以某点为圆心、圆形遮罩向外扩张，透明度从 0.35 升到 1。
  - `neon`：前 65% 在亮暗间随机跳几次，然后稳定爬升，像霓虹管点亮。
  - 两种方式都伴随文字解码：字符先随机替换为 `01#%&/<>=+*:░▒`，再逐渐还原。
- **数值平滑**统一用指数趋近 `1 − e^(−r·dt)`，与帧率无关。主读数用慢速（时间常数约 1.2 秒，只显示整数），条形和梳齿用快速，避免每秒采样的抖动让数字乱滚。
- **时间采样**与帧率解耦：网络波形固定 30Hz，负载历史 1Hz。
- 闪烁只用于异常（无信号、低电量），常态元素不闪。

## 10. 深度与视差

画面随鼠标位置微微转动，鼠标 3 秒不动或离开窗口时缓慢回正。强度 `parallax`（默认 0.5，0 关闭）。

| 层 | 行为 |
| --- | --- |
| 背景点阵 | 远层，按 `BG_DEPTH = 0.4` 与鼠标**同向**移动，整像素偏移 |
| 骨架 | 不在 Canvas 里移动，保持像素对齐；后处理里按穹面深度场错开采样（中心最近、左右边缘最远），线条连续不断 |
| 读数格、规格表 | 近层（`nearLayer`），**逆着**鼠标平移完整的视差量（`PAR_PX = 20`） |
| 多行文本 | 组内轻微错位：主读数 0，次要行 `Z1 = −0.12`，第三行 `Z2 = −0.25`，日志越旧越靠后 |
| 整体 | 后处理里做透视转角，最大 `PAR_DEG = 3°` |

层次感主要来自组与组之间，同一组内的深度差要小，否则显得松散。跨层连线用 `pin()` 换算坐标。

## 11. 后处理（WebGL2）

单个全屏片元着色器，对 Canvas 结果做：

- **曲面**：中心略缩、边缘拉伸，四边中点贴边、四角轻微裁切，不留黑边。默认 `curve = 0.5`。
- **径向色差**：越靠边越明显，强度随曲面一起变。
- **扫描线**：每 3 个 CSS 像素一条，外加一条缓慢下行的亮带。默认 `scan = 0.4`。
- **辉光**：三档 mipmap 模糊叠加，减去阈值避免抬亮背景。默认 **关闭**（`glow = 0`），关闭时不生成 mipmap。
- `?fx=0` 整体关闭，此时直接显示 Canvas。

## 12. 声音（WebAudio 现场合成）

不使用音频文件，全部由振荡器合成，主输出带 130ms 的短反馈延迟营造空间感。

| 事件 | 声音 |
| --- | --- |
| 开机 | 三角波从 180Hz 扫到 1440Hz |
| 组件载入 | 短促提示音，音高随载入顺序按七声音阶上升 |
| 载入完成 | 72→38Hz 低频下沉，叠加高频提示 |
| 告警进入 / 解除 | 两声方波 + 上扬 / 一声下行；每类告警音高不同 |
| 挂载 | 1560Hz + 上扬双音 |
| 环境底噪 | 两个微失谐的 55Hz 锯齿波经低通，截止频率随 CPU / GPU 负载升高（负载越高越"亮"） |

高频率事件（日志每两三秒一条）**不配声音**，否则会变成持续的"啾啾"声。音量默认 0.35，可单独关闭底噪。

## 13. 控制面板（DOM）

叠在后处理画布之上，不受畸变影响：

- 直角矩形、1px `line` 边框，不做切角和圆角；分组之间用 1px 横线分隔。
- 标题字距 0.25–0.3em，全大写；正文 12px，说明 10–11px。
- 滑块：2px 轨道，已填充部分为 `hot`；拇指是 7×14 的 −20° 斜切块。开关是 30×12 的矩形滑块。选中态用 `hot` 描边，焦点用 1px `hot` 外框。
- 颜色通过 `--hud-fg` / `--hud-bg` / `--hud-line` / `--hud-dim` / `--hud-hot` 从当前主题取值。
- 兼容性限制：不用 `backdrop-filter`，也不用原生 `<select>`（两者都会让 Wallpaper Engine 的离屏 CEF 崩溃），帧率用分段按钮代替下拉框。

## 14. 新界面检查清单

做同风格的新 HUD 时逐条对照：

- [ ] 内容挂在引导线上，而不是放进独立卡片；左右成对的信息镜像摆放。
- [ ] 只用主题 token 着色，切换 9 套主题都可读，`mono` 下仍能区分主次。
- [ ] 线宽只用 2.5 / 1.5 / 1.25 / 1 四档；节点处断线留环。
- [ ] 标签用 `600 9px` Chakra Petch、字距 2px、全大写；Canvas 里会变的数字用 JetBrains Mono。
- [ ] 每个数据字段都有 NO SIGNAL 状态，不显示假数据。
- [ ] 数值走指数平滑，采样与帧率解耦。
- [ ] 动效只用于开屏、挂载、数据流动和异常；常态不闪烁。
- [ ] 有视差时近层、骨架、远层分开，组内深度差小。
- [ ] 高频事件不配声音。
